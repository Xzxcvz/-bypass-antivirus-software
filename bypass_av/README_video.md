# WindowsUpdate 红队实战工具 — 技术原理讲解

## 一、概述

这是一个**红队渗透测试 / 攻击模拟**工具，演示了在**没有公网 VPS、不需要目标用户配合**的前提下，如何从外网连接到内网目标主机。

### 核心能力
- 在目标机上启动一个 **TCP 反向控制通道（bind shell）**
- 自动通过 **UPnP 协议**在路由器上开启端口映射
- 将目标的 **身份信息（主机名+硬盘序列号）和公网 IP** 发送到攻击者面板
- 支持 **三种通信模式**，适应不同网络环境

## 二、技术原理

### 2.1 免杀技术（Bypass AV）
```
┌─────────────────────────────────────────────────┐
│  WindowsUpdate.exe                              │
│   ├─ API Hashing（djb2 哈希，无导入表）            │
│   ├─ RC4 加密字符串（避开静态特征扫描）             │
│   ├─ ntdll 脱钩（从磁盘加载干净 ntdll 覆盖内存）    │
│   ├─ ETW 修补（绕过 Windows 事件跟踪）             │
│   ├─ Hell's Gate（间接系统调用，绕过用户态 Hook）   │
│   └─ 196KB 填充 + 假签名（增大体积绕开 ML 检测）    │
└─────────────────────────────────────────────────┘
```

关键设计：**不依赖任何第三方库**，所有 API 通过 PEB 手动解析，导入表完全隐藏。

### 2.2 UPnP 自动端口映射
```
目标机                       路由器                   公网
  │                          │                      │
  ├─ PowerShell COM ────────→│                      │
  │  New-Object              │                      │
  │  HNetCfg.NATUPnP        │                      │
  │                          │                      │
  │  Add(54321, TCP) ──────→│  开放 54321 端口      │
  │                          │  ←──────────────     │
  │  GetExternalIPAddress()  │                      │
  │  ←──── 公网 IP ─────────│                      │
  │                          │                      │
  │  POST 到面板             │                      │
  │  ──→ maxapi112.netlify   │                      │
  │      .app/api/receive    │                      │
  │                          │                      │
```

**UPnP（通用即插即用）** 是路由器上广泛支持的标准协议。工具通过 PowerShell 调用 Windows 内置的 COM 接口 `HNetCfg.NATUPnP` 与服务端通信，无需安装任何额外软件。

### 2.3 通知机制（双保险）
```
┌─ 方案 A（PowerShell）─────────────────────────┐
│  PowerShell → WinHttp COM → HTTPS POST        │
│  优点：UPnP + 通知一条龙                      │
│  缺点：依赖 PowerShell 执行策略                │
└───────────────────────────────────────────────┘

┌─ 方案 B（C 代码直发，备用）────────────────────┐
│  WinHTTP API → winhttp.dll → HTTPS POST       │
│  优点：100% Win32 API，不依赖任何外部组件      │
│  缺点：无法做 UPnP（只发通知）                 │
└───────────────────────────────────────────────┘
```

方案 B 使用 Windows 内置的 `WinHTTP` 库直接发送 HTTPS 请求，不走 PowerShell、不调 COM 组件，即使脚本执行策略被锁也能发出通知。

### 2.4 通信加密 —— XOR 流加密
```
连接建立后，所有流量经过 XOR 加密：

密钥： 0x42, 0x7A, 0x1F, 0xE3, 0x9C, 0x55, 0xB0, 0x2D
模式： 双方维护累计位置计数器（非固定轮换）

明文 → XOR 密钥[pos % 8] → 密文
                              ↓
密文 → XOR 密钥[pos % 8] → 明文
pos++ （每条消息后位置递增）
```

防止流量被 IDS/IPS 规则匹配（如匹配 "cmd.exe" 字符串）。

### 2.5 自动提权与持久化
```
首次运行（需要 UAC 管理员权限）：
  1. 复制自身到 %APPDATA%\Microsoft\Windows\Caches\runtime.exe
  2. 创建隐藏备份（同目录下 Windows\ 文件夹）
  3. 添加 HKCU\Run 开机启动项
  4. 禁用 UAC（重启生效）
  5. 重命名原文件为 .bak
  6. 启动 runtime.exe 后退出

后续运行（开机自启，UAC 已禁用）：
  直接执行 payload 逻辑
```

## 三、三种工作模式

### 模式 1：UPnP 模式（默认）
```
适用：目标在 NAT 后，路由支持 UPnP
原理：自动开端口，从外网直连
命令：python3 c2client.py <公网IP> 54321
```

### 模式 2：隧道模式
```
适用：目标在不支持 UPnP 的网络
原理：目标主动连接你的中继服务器
需要：一台有公网 IP 的中继机
```

### 模式 3：FRP 模式
```
适用：最复杂的网络环境
原理：通过 frpc 建立反向代理隧道
需要：一台 VPS
```

## 五、防御建议

### 如何检测这种攻击？
| 检测点 | 方法 |
|--------|------|
| UPnP 端口 | 查看路由器 UPnP 映射表，检查 54321 端口 |
| 进程异常 | `runtime.exe` 监听 TCP 54321（非微软数字签名） |
| 启动项 | `HKCU\...\Run\WindowsUpdate` → AppData 目录 |
| 网络连接 | 目标机存在对外 `ESTABLISHED` 的 54321 连接 |
| UAC 状态 | `EnableLUA = 0`（被禁用） |

### 防护措施
1. **关闭路由器 UPnP 功能**（绝大多数用户不需要它）
2. **启用 Windows Defender 实时保护 + 云防护**
3. **不要双击来源不明的 exe 文件**
4. **保持 UAC 开启（默认级别以上）**
5. **使用 Sysmon / EDR 监控异常的端口监听行为**
